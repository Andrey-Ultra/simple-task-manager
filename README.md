# simple-task-manager

Простая очередь задач на C++ с HTTP-API. Клиенты отправляют задачи, воркеры забирают их и возвращают решения. Если воркер завис, задача автоматически возвращается в очередь.

Задача для сервера — просто строка (текст, JSON, ссылка). Что с ней делать, решают клиент и воркер.

## Сборка и запуск

Нужны CMake ≥ 3.24 и компилятор с C++20. Зависимости ([cpp-httplib](https://github.com/yhirose/cpp-httplib), [nlohmann/json](https://github.com/nlohmann/json)) CMake скачает сам.

```bash
cmake -S . -B build
cmake --build build
./build/simple_task_manager
```

Сервер слушает порт `8080`. Таймаут выполнения задачи — 30 секунд (меняется в `main.cpp`).

## Как это работает

```
клиент ──POST /tasks──▶ [ очередь ] ──POST /worker/take──▶ воркер
   ▲                                                          │
   └────────── GET /tasks/{id}/answer ◀── POST …/answer ──────┘
```

Статусы задачи: `in queue` → `in work` → `complete`.

## API для клиента

| Метод и путь | Описание | Ответ |
|---|---|---|
| `POST /tasks` | Отправить задачу (тело запроса — текст задачи) | `200` + `id`; `400`, если тело пустое |
| `GET /tasks/{id}/status` | Узнать статус | `200` + `in queue` / `in work` / `complete`; `404`, если задачи нет |
| `GET /tasks/{id}/answer` | Забрать ответ. После этого задача удаляется | `200` + ответ; `404`, если ответа ещё нет |
| `DELETE /tasks/{id}` | Отменить задачу | `200`; `404`, если задачи нет |

## API для воркера

| Метод и путь | Описание | Ответ |
|---|---|---|
| `POST /worker/take` | Взять задачу из очереди | `200` + `{"id": 7, "task": "..."}`; `204`, если очередь пуста |
| `POST /worker/tasks/{id}/answer` | Вернуть решение (тело запроса — ответ) | `200`; `409`, если задача не в работе |
| `POST /worker/tasks/{id}/release` | Вернуть задачу в очередь без решения | `200`; `409`, если задача не в работе |

> `id` воркера приходит из `/worker/take` и отличается от `id` клиента. Если воркер не успел за таймаут, задача возвращается в очередь с новым `id`, а его запоздавший ответ получает `409`.

## Пример

```bash
# клиент: отправить задачу
curl -X POST localhost:8080/tasks -d '2+2'          # → 0

# воркер: взять, решить, вернуть
curl -X POST localhost:8080/worker/take             # → {"id":0,"task":"2+2"}
curl -X POST localhost:8080/worker/tasks/0/answer -d '4'

# клиент: проверить и забрать ответ
curl localhost:8080/tasks/0/status                  # → complete
curl localhost:8080/tasks/0/answer                  # → 4
```

## Ограничения

- Данные хранятся в памяти и пропадают при перезапуске.
- Нет авторизации: сервер рассчитан на доверенную сеть.
